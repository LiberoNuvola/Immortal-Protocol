Protocol · universal layer

Economic rules that stay explicit.

IMMORTAL is a chain-neutral, application-neutral economic protocol for systems that need explicit state, protected obligations, deterministic transitions, safety constraints and auditable evidence.

See verification status →Read the source hierarchy
STATE

Canonical state

The protocol reasons from authoritative state and declared evidence rather than presentation, submission order or operator discretion.

PROTECTION

Obligations first

Protected capital, liabilities and mandatory future costs are accounted for before discretionary surplus can be used.

TRANSITIONS

Fail closed

An action is admissible only when the applicable economic and safety predicates hold. Invalid transitions do not become valid because execution is convenient.

Ownership boundary

Protocol · Adapter · Application

IMMORTAL owns universal semantics. An adapter owns chain mechanics and evidence transport. An application owns domain-specific policy. This boundary is a first-class design constraint.

Verification boundary

Specification is not certification.

Specification→Model / proof→Implementation→Conformance→Deployment evidence

The project deliberately keeps these evidence classes separate. A mathematical result does not certify a deployment; a green test does not become a ledger witness merely by being green.
