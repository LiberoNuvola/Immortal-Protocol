## Runner contract

The P2.8 runner is fail-closed. It requires:
- exact Plutus validator artifacts,
- transaction CBOR,
- consumed UTxO packet,
- era-specific protocol parameters,
- typed timing context,

## Preprod materialization path

New workflow:

`.github/workflows/immortal-preprod-ledger-evidence.yml`

New materializer:

`audit/cardano-integration/materialize-preprod-p28-context.mjs`

The materializer is deliberately non-signing. It accepts only an already-submitted transaction hash and obtains:
- transaction CBOR and transaction metadata from Koios Preprod,
- exact consumed UTxOs,
- protocol parameters for the transaction's epoch,
- era/epoch timing from Demeter/Ogmios,
- SystemStart from Demeter/Ogmios.

It rejects a transaction unless its epoch is identified as **Babbage**, because the current P2.8 runner is Babbage-typed.

## Important limitation

The typed `EpochInfo` constructor is derived from the exact era parameters returned by Ogmios for the transaction epoch. This is deterministic typed-context construction; it is not a claim that the runner has reconstructed a complete historical consensus state beyond the inputs required by its current evaluation surface.

## Acceptance criteria

A complete P2.8 packet becomes VERIFIED only when the fresh workflow records:
- native Babbage transaction decode,
- native UTxO decode,
- native PParams decode,
- typed EpochInfo decode,
- typed SystemStart decode,
- `evalTxExUnitsWithLogs` completion,
- explicit A/B or typed-failure result,
- binding hashes for all source/context/evaluation artifacts.

It may be useful for exercising a Reveal-shaped transaction, but the script name or a submitted transaction from it is not sufficient to classify that transaction as the intended production path.

**Qualification rule:** do not submit a transaction from this harness as the P2.8 witness unless the transaction's actual inputs, policy/script hashes, ticket/pool assets, datum/redeemer and deployment binding are independently shown to match the intended production Reveal path. A transaction hash alone proves neither that path identity nor native-ledger acceptance.

The non-signing P2.8 workflow remains the correct evaluator consumer once a qualifying already-submitted Preprod transaction exists. Its raw-context materializer is not itself the production-path classifier; that classification must be attached to the evidence packet before the C5/native-witness gate can close. No native evaluation result is claimed by this source review.
