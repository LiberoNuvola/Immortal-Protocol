1. The inline Reveal builder reaches 18,365 bytes against the 16,384-byte default transaction-size ceiling.
2. Factory script CBOR sizes are 9,760 bytes (PrizeValidator) and 7,543 bytes (B1PrizePool), total 17,303 bytes. These are static script sizes, not transaction size.
3. With diagnostic execution ceilings raised, Lucid 0.10.11 reports:
   `Spend[0] attempted to case a non-const Value Con(ProtoPair(...))`.
4. Lucid Evolution 0.6.2 reproduces the same runtime class.
5. Scalus UPLC 0.1.4 reproduces the equivalent `VCon(Pair(...))` failure.
6. Therefore the current evidence is an evaluator/harness blocker, not a validator-semantic verdict.
7. `nativeUplc: false` in Lucid 0.10.11 requires a provider path capable of Haskell evaluation; the in-memory Emulator does not supply that path.

## Fixture provenance audit — 2026-09-21

The historical P2.8-B.1 diagnostic branches were re-opened to recover the exact Reveal construction rather than recreating it from memory.

- PR #1 contains `src/__tests__/immortal-cardano-reveal-emulator-b1.mjs`, the fixture used for the 18,365-byte measurement.
- That fixture parameterizes the repository's actual PrizeValidatorFactory and B1PrizePoolFactory artifacts and mirrors the current `src/gameFlow.ts` Reveal shape: Prize spend with `Reveal(secret)`, B1PrizePool spend with `TicketRevealed(priceUsdm)`, and two continuing outputs.
- The fixture itself explicitly states that it is **synthetic and not a Preprod transaction**. Its setup creates fresh emulator UTxOs and therefore does not provide real Cardano transaction inputs, transaction identifiers, ledger state, protocol parameters, epoch/system-start context, or a submitted ledger transaction.
- Consequently, the historical fixture is valid evidence for reproducing the previous **emulator** diagnostic, but it is not sufficient evidence for the normative Cardano-ledger A/B acceptance criterion.

This distinction closes an important ambiguity: we have recovered the exact historical diagnostic fixture, but we have **not** recovered a real ledger transaction context. The runner must therefore remain fail-closed rather than promote the synthetic emulator fixture into a ledger verdict.

## Normative context required to continue

The official Cardano ledger API defines `evalTxExUnits` / `evalTxExUnitsWithLogs` over the concrete transaction, relevant UTxO set, protocol parameters, epoch information, and system start, returning either ExUnits or a `TransactionScriptFailure`. citeturn1search0

For P2.8-B.1 the missing evidence is therefore concrete, not conceptual:

1. the exact serialized Reveal transaction (or an equivalent exact ledger transaction reconstruction);
2. the exact input UTxOs referenced by that transaction, including their datum/value/script provenance;
3. the matching ledger protocol parameters/cost model;
4. the epoch information and system-start required for Plutus context translation;
5. the exact script witnesses/context needed by the ledger evaluator.

Until these are available together, a synthetic reconstruction would violate the audit rule established by Gate 16: unavailable required evidence produces SAFE STALL rather than an invented measurement.
