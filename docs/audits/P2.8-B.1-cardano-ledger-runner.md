## Normative context required to continue

The official Cardano ledger API defines `evalTxExUnits` / `evalTxExUnitsWithLogs` over the concrete transaction, relevant UTxO set, protocol parameters, epoch information, and system start, returning either ExUnits or a `TransactionScriptFailure`. citeturn1search0

For P2.8-B.1 the missing evidence is therefore concrete, not conceptual:

1. the exact serialized Reveal transaction (or an equivalent exact ledger transaction reconstruction);
2. the exact input UTxOs referenced by that transaction, including their datum/value/script provenance;
3. the matching ledger protocol parameters/cost model;
4. the epoch information and system-start required for Plutus context translation;
5. the exact script witnesses/context needed by the ledger evaluator.

Until these are available together, a synthetic reconstruction would violate the audit rule established by Gate 16: unavailable required evidence produces SAFE STALL rather than an invented measurement.

## Evaluator mode and raw-artifact binding — 2026-09-25

The runner exposes an explicit `--evaluate` mode. The real P2.8 workflow invokes this mode; the generic audit runner can still exercise compilation/context safety without requesting evaluation.

This is an evidence-binding hardening step only. It does not establish the final P2.8 A/B result until the real evidence workflow executes on the exact Reveal packet.


## 2026-09-26 — Exact timing provenance hardening

A concrete context-fidelity issue was identified in the runner's EpochInfo construction. Yaci Store's Blockfrost-compatible `/genesis` endpoint serializes fractional slot lengths as rounded-up integers; its upstream test suite explicitly demonstrates `0.1` seconds becoming `1`. The Yaci DevKit `info` surface exposes the exact cluster `Slot Length`, together with `Start Time` and `Epoch Length`.

The P2.8 materializer now preserves that exact devkit record inside `epoch-info.json`. The native runner uses the captured `Slot Length` for `EpochInfo`, verifies the `Epoch Length` against the structured genesis response, and verifies `Start Time` against the genesis `system_start` value before constructing the typed `SystemStart`.

This removes the specific fractional-slot timing ambiguity from the implementation. It does not constitute the final P2.8 A/B result: the exact Yaci packet must still be executed by the native ledger evaluator and its report artifact preserved.
