# P2.8 — Cardano Ledger-Native Evaluation Research Pass — 2026-09-27

## Classification

**Research / non-normative.** This note records upstream API facts and the evidence boundary. It does not certify a transaction.

## Upstream API fact

Cardano ledger exposes:

`evalTxExUnitsWithLogs`

with inputs including:

- protocol parameters;
- concrete transaction;
- current/relevant UTxO set;
- EpochInfo;
- SystemStart.

It returns a redeemer report containing either script failure or execution units plus evaluation logs.

Primary reference:
https://cardano-ledger.cardano.intersectmbo.org/cardano-ledger-alonzo/Cardano-Ledger-Alonzo-Plutus-Evaluate.html

## Consequence for IMMORTAL P2.8

A synthetic evaluator context is not equivalent to ledger-native evaluation.

The minimum reproducible packet therefore remains:

- tx.cbor;
- exact relevant UTxO set;
- protocol parameters;
- EpochInfo;
- SystemStart;
- exact era/type decoding;
- runner commit and dependency lock;
- evaluator result and logs;
- manifest binding all inputs to the exact run.

## Evidence hierarchy

The following must remain distinct:

1. typed transaction decoding;
2. successful evaluator construction;
3. native ledger execution result;
4. real Yaci/devnet execution;
5. real Preprod submission;
6. deployment certification.

Passing (1) does not imply (3). Passing (3) does not imply (5).

## Current research implication

The repository's P2.8 runner already identifies the correct next boundary: materialize exact UTxO, EpochInfo and SystemStart, then invoke the native evaluator.

The research does not justify any shortcut such as:

- approximating EpochInfo;
- fabricating SystemStart;
- reconstructing only a subset of protocol parameters;
- replacing native ledger types with application-level lookalikes;
- treating a local evaluator success as Preprod evidence.

## Acceptance target

P2.8 closes at the requested layer only when the exact-head transaction has a persisted native-ledger evaluation packet whose inputs and outputs are reproducible.
